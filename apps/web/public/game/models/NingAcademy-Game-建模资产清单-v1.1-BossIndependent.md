# NingAcademy Game · 完整建模资产清单与美术规格（v1.1 · Boss 独立资产修订）

来源：`NingAcademy-3DFPS-V1-实施计划-rev2.1-BossIndependent.md` + `NingAcademy-Game-Complete-Product-Design-v1_0.docx`
用途：列出 V1 范围内**每一个需要建模的地方**，并给出每个模型应该做成什么样。Boss 规则已修订为：**无 Boss 母体、每 Boss 独立资产、Boss 不绑定地图、同一 Boss 同时支持 AI/PvE 与玩家控制。**

## 0. 全局规则（先读这一节，它决定后面所有模型的做法）

### 0.1 三条不可违反的内容约束

| 约束 | 出处 | 对建模的直接影响 |
|---|---|---|
| 无血、无断肢、无碎块、无写实尸体 | rev2 §4.9.1，敌人显示名"结晶体 / Thrall" | 敌人不能做腐肉僵尸。方向是**有机躯体被晶体侵蚀/替换**。死亡不留尸体，0.5 秒内解析成光尘 |
| 弱点必须"核心暴露、轮廓变化" | rev2 §4.9.1 | 每个敌人要有**独立的核心网格 + 覆盖它的可碎外壳**，不是贴图上画个红点 |
| 四生态"形状、裂纹和音色都不同，不能只换颜色" | rev2 §4.9.1 | **只约束普通 Thrall/精英的生态表现**，见 0.3；Boss 不随地图生态换外观 |

### 0.2 预算（rev2 §4.9.4 明确写死，建模必须倒推）

- 大厅 ≤15MB；选定生态可玩资源 ≤50–60MB；完整生态 ≤80MB；手机低档可玩 ≤45MB
- 结晶表现另有独立配额：下载 ≤8MB、GPU 常驻 ≤16MB
- 同屏敌对实体上限：房屋 20 / 草地 30 / 沙漠 40 / 地狱 50
- 手机基线 4GB 中端机、540–720p、稳定 30fps

由此推出的**面数与贴图建议**：

| 资产类别 | 三角面 | 贴图 | 说明 |
|---|---:|---|---|
| 幸存者角色（第三人称） | 8k–12k | 1×2048  | 最多同屏 8 个 |
| 第一人称手臂 | 6k–8k | 1×1024 | 只有自己看得到，可以精细 |
| 敌人基础体 | 2.5k–4k | 共享 1×1024 生态图集 | 同屏 50 个，这是最关键的预算点 |
| 敌人特殊体/精英体 | 4k–6k | 复用生态图集 + 1×512 专属 | |
| 生态晶簇挂件 | 300–800 / 套 | 复用生态图集 | |
| Boss | 20k–30k / 个 | **每 Boss 自己的 2×2048** | 同屏 1–4 个；禁止 Boss 间共享贴图/材质资产 |
| 武器第一人称模型 | 8k–15k | 1×2048（PBR） | 玩家整局盯着看 |
| 武器第三人称/挂背 | 1.5k–3k | 复用第一人称贴图降级 | |
| 部署物/道具 | 1k–3k | 共享 1×1024 道具图集 | |
| 地图模块 | 3k–8k / 模块 | 共享 trim sheet 2×2048 / 生态 | 必须带预烘焙碰撞与导航出入口 |

### 0.3 共享骨骼与挂件策略（Survivor / Thrall 保持现状；Boss 明确例外）

- **幸存者 5 职业共用一套人形骨骼**，只换网格与体型比例。动画、IK、武器挂点全部共用。**保持现状，不修改。**
- **普通敌人 Thrall/Zombie 共用一套简化人形骨骼**（比幸存者少手指、少表情骨）。基础体 / 特殊体 / 精英体 / 僵尸玩家普通体全部套这一套。**保持现状，不修改。**
- **普通 Thrall 的生态差异继续用挂件实现**：一个基础躯体 + 每生态 3–4 个可替换晶簇部件（肩背晶簇、胸腔核心、头部结晶、小腿结晶）。换挂件 + 换材质 = 剪影不同 + 裂纹不同，同时躯体只做一次。**这一规则不适用于 Boss。**
- **Boss 是硬例外**：禁止 Boss 母体、`BossCanonical`、Boss Base、跨 Boss 共用 Skeleton、跨 Boss 共用动画文件、跨 Boss 共用 Mesh、材质、贴图、可破坏件。每个 Boss 从零作为完整独立资产包交付。
- 可以统一的只有**接口命名**（例如动画状态名、socket 语义、Hitbox 数据格式），方便 Babylon.js/服务器调用；统一接口不等于共享资产。
- Survivor / Thrall 继续预留原 socket：
  - `sk_weapon_r` 右手主武器
  - `sk_weapon_back` 背部收纳
  - `sk_head` 头部（头盔/词缀附件）
  - `sk_core` 弱点核心中心（敌人必备）
  - `sk_shard_00..07` 碎裂发射点（敌人必备，10–20 片晶体从这里生成）
- Boss 也使用同名**语义接口**时，socket 必须在该 Boss 自己的 Skeleton 中单独创建，不得引用其他 Boss Skeleton。

### 0.4 材质与命名

- 材质分层固定为四类，方便全局配色：`Leather` / `Cloth` / `Metal` / `Crystal`
- 敌人材质必须预留**裂纹遮罩通道**（第二套 UV 或顶点色），共享 shader 靠它做裂纹扩散与溶解
- 命名：`SUR_warrior_body` / `ENM_base_grass` / `WPN_ar_fp` / `MAP_house_corridor_a` / `DEP_turret`。Boss 使用独立命名，例如 `CHR_BOSS_Hunter_v01` / `CHR_BOSS_Swarmer_v01` / `CHR_BOSS_Plague_v01` / `CHR_BOSS_IronShell_v01`，各自有独立 manifest。
- 每个资产随 `asset_manifest_id` 发布（rev2 §4.2），改动几何 = 改 manifest = 客户端 `layout_hash` 校验会失败，所以**地图模块定版后不要随便改尺寸**

## 1. 幸存者角色（5 个，rev2 §4.3.1）

共同基准 100 HP / 20 护甲。5 个职业必须**在 720p 手机屏幕上靠剪影就能分辨**，不能靠脸和贴图细节。

### 1.1 战士 Warrior（105 HP / 22 护甲 / 武器与近战 +5%）

你现有的版本偏"普通皮甲"，需要往中重甲推。

**体型**：五头身偏壮，肩宽是最宽处，上半身重下半身轻，站姿前倾带攻击性。

**部件**
- 牛角头盔（角向外向上，不要向下弯，向下会削弱肩线）
- 大胡子
- 皮甲底层
- **金属胸甲片**（横向 3–4 条，覆盖胸口中央，留出腹部活动）
- **腹部金属片**（比胸甲窄，做成叠瓦状）
- **左右肩甲**（左右**不对称**——持武器那侧做大一号，另一侧留出挥动空间）
- **腰部装甲裙**（4–6 片垂坠甲片，只到大腿一半，不要到膝盖，否则变守卫）
- 护腕（金属，宽）
- 厚腰带 + 侧挂皮囊
- 皮靴 + 金属靴头

**配色**
- Leather：深棕 `#4A3524`
- Cloth：暗红 `#7A2B26`
- Metal：铁灰 `#5C6068`
- 点缀：铜色 `#A9743C`，只用在扣件、角尖、腰带扣

**最终轮廓**：中重甲 + 大武器 + 粗壮 + 攻击性强。重量感排序：守卫 > 战士 > 刺客/法师/医疗。

**技能可视化需求**：8 米战吼需要头部/胸口有可发光的部件；6 米震荡锥需要手部有一个可发光的击打点。

---

### 1.2 医疗 Medic（治疗 +10% / 武器伤害 −3%）

**体型**：标准比例，偏轻，肩比战士窄一档，站姿直立不前倾。

**部件**
- 无头盔，改用**战术头巾 + 护目镜推到额头上**（露脸=可信赖感）
- 轻质织物外套，长到大腿，**下摆开衩**（跑动时飘，和战士的硬甲裙区分）
- 胸前 **X 形背带 + 多个小药囊**（这是医疗最强的剪影特征）
- **背包**：大、方、带侧袋，背包上有一个可发光的圆形指示灯（治疗脉冲时亮）
- 小臂上一个**腕式装置**（治疗脉冲的施法源，必须能发光）
- 单侧小腿绑带 + 备用绷带卷
- 只有前臂和小腿有极轻的护片，**不要金属胸甲**

**配色**
- Cloth：米白 `#D8D2C4` / 浅灰
- Leather：中棕 `#6B563C`
- Metal：哑光银 `#9AA0A6`（少量）
- 点缀：**青绿 `#3FBFA0`**（发光色，全队唯一使用这个色的角色）

**最终轮廓**：轻装 + 大背包 + 前胸挂满小袋 + 圆润无尖角。

**技能可视化需求**：治疗脉冲从腕部装置发出；救援屏障需要角色能举起一只手，手心朝外。

---

### 1.3 法师 Mage（95 HP / 18 护甲 / 技能与状态伤害 +5%）

**体型**：偏瘦高，是 5 个职业里**最高最窄**的剪影。

**部件**
- 兜帽（戴起，脸部半阴影，不做全脸）
- 长袍 + **不对称披风**（只有一侧长到小腿，另一侧到腰）
- 肩部有**悬浮结晶**（不与身体接触，靠动画浮动，是法师最强识别特征）
- 前臂缠绕布条 + 刻纹金属环
- 腰间挂 3–4 个**小晶石吊坠**
- 靴子做软底短靴，不要重靴
- **不要肩甲、不要胸甲**

**配色**
- Cloth：深靛蓝 `#2E3A6B`
- Leather：黑棕 `#3A3028`
- Metal：暗银 `#7C8290`
- 点缀：**冰蓝 `#6FC8FF`**（对应冰霜领域）+ 少量紫 `#8B6FD1`（对应奥术跳跃）

**最终轮廓**：高、窄、飘、悬浮件多、几乎无金属。

**技能可视化需求**：奥术跳跃是四目标递减，需要手部有清晰的发射点；冰霜领域是 6 米地面领域，脚下要有可发光的环形结构或法阵挂点。

---

### 1.4 刺客 Assassin（95 HP / 18 护甲 / 移速与弱点与近战 +5%）

**体型**：中等身高，最瘦，重心低，站姿含胸微蹲。

**部件**
- 面罩遮住下半张脸 + 窄目镜（**发光的窄眼缝**，暗处唯一可见特征）
- 紧身衣 + 分片式软甲（片小、密、贴身，不能鼓出来）
- **腿部与腰后挂多把飞刀/短刃**（不用都能用，是剪影用的）
- 手部：**手套 + 前臂刃鞘**
- 膝盖与手肘有小护片（唯一硬件）
- **无披风、无长下摆**（会破坏"快"的感觉）
- 后腰一个小型能量装置（突进技能来源，可发光）

**配色**
- Cloth：炭黑 `#242629`
- Leather：深灰紫 `#3B3641`
- Metal：暗钢 `#6A6E75`
- 点缀： **橙红 `#FF6B3D`**（二选一，用在目镜与弱点标记装置上）

**最终轮廓**：瘦、低、贴身、多小刃、无飘动件。

**技能可视化需求**：弱点标记 10 秒，需要角色有一个"投掷/指向"的可视源；服务器扫掠突进无无敌，所以**不要做拖影以外的护盾类视觉**，避免玩家误判自己无敌。

---

### 1.5 守卫 Guardian（110 HP / 30 护甲 / 伤害与移速 −3%）

**体型**：最壮最宽，四头半身，肩宽夸张，腿粗，站姿稳定重心低。这是全队最重的剪影，必须明显比战士重。

**部件**
- 全覆盖头盔，**面甲带横向观察缝**（不露脸，与战士的露脸大胡子形成对比）
- 完整金属胸甲（整片，不是战士的分片）
- 大型**方形肩甲**（左右对称，比战士大一倍，边缘做厚）
- 前臂大护手 + 手背金属板
- **完整腰甲裙到膝盖** + 大腿护片
- 重靴 + 金属胫甲
- 背部有**晶盾发生器**（一个可以看出"会展开"的装置，对应 180 HP 晶盾）
- 挑衅技能需要胸口有一块可发光的区域

**配色**
- Metal：深钢蓝灰 `#4A5568`（主色，占比最大）
- Leather：深棕 `#3E2F22`
- Cloth：靛蓝 `#26355C`
- 点缀：**晶蓝 `#5FD8E8`**（对应晶盾，与法师的冰蓝要拉开明度）

**最终轮廓**：重甲 + 方肩 + 全包裹 + 低重心 + 慢。

| 资产 | 规格 |
|---|---|
| 第一人称手臂 | 1 套骨骼 + **5 套手部/前臂网格**（对应 5 职业的手套与护腕）。只做到手肘上方 |

## 2. 敌人：结晶体 / Thrall（rev2 §4.1、§4.9.1）

### 2.1 造型总方向

不是腐烂人类。方向是：**人形躯体被晶体从内部撑开、部分骨肉被晶体替换**。

- 保留人形轮廓与走路方式（玩家要能识别是"敌人"）
- 皮肤区域做成灰化、干化、无血色，**不做伤口、不做外露内脏**
- 晶体从胸腔、肩背、颅骨破出，是"生长"不是"插上去"
- 关节处可以有晶体填充，暗示身体被替换
- 死亡时整体解析，所以**网格必须能被 10–20 片晶体碎片替代**，不能有太长的悬垂件

### 2.2 基础体（1 个躯体 + 4 套生态挂件）

**躯体**（`ENM_base_body`，2.5k–4k 面）
- 中等身高，略驼背，双臂下垂偏长
- 胸腔中央是**弱点核心位**：外面一层可碎的晶壳，里面一个发光核心球
- 衣物做成破损的普通平民服（不同生态换配色即可）

**四套生态挂件与配色**

| 生态 | 晶体形状 | 主色 | 裂纹表现 |
|---|---|---|---|
| 房屋 | **紫色晶质**，短粗六棱柱，簇状密集 | 晶体 `#8B5CF6`，躯体灰紫 | 直线裂纹，边缘锐利 |
| 草地 | **绿色孢子化**，圆润菌伞状 + 细丝 | 晶体 `#4ADE80`，躯体灰绿 | 网状扩散裂纹，像叶脉 |
| 沙漠 | **风沙崩解**，扁平片状、边缘被磨圆 | 晶体 `#E8C468`，躯体沙灰 | 剥落式裂纹，边缘有颗粒感 |
| 地狱 | **黑曜 + 橙色余烬**，尖锐长刺 | 晶体 `#1C1917` + 内发光 `#FF7A1A` | 熔线裂纹，内部透出橙光 |

每套挂件包含：肩背晶簇、胸腔核心壳、头部结晶、小腿结晶。**四套挂件的剪影必须能一眼分辨**——房屋簇状鼓包、草地有细丝外扩、沙漠是扁平外张、地狱是长尖刺。

### 2.3 特殊体（4 个，产品设计书 §12）

在基础躯体上做变形，共用骨骼与动画基础。

| 特殊体 | 造型要点 | 剪影关键词 |
|---|---|---|
| **远程吐息型** | 头部/胸腔膨大成一个**发光腔体**，脖子拉长，双臂萎缩 | 大头 + 细手臂 |
| **冲锋型** | 上半身极度前倾，肩背晶体聚成**冲角**，腿部粗壮，双臂后甩 | 四足预备姿 + 前突尖角 |
| **控制型** | 双臂异常长，手掌张开且指部结晶化成钩爪，身体细 | 长臂垂地 |
| **治疗型** | 背部有一个**悬浮晶球**（不与身体接触），身体佝偻，双手护在胸前 | 背后浮球 |

治疗型必须最容易被识别——它是优先击杀目标，剪影要最独特。

### 2.4 精英变体（4 个，rev2 §4.1.1）

原文明确：**精英是不同的行为模板，不是"HP 更高的普通怪"**，所以外观必须显著不同，不能只放大。

| 精英 | 造型要点 | 弱点设计 |
|---|---|---|
| **护盾型** | 前臂或胸前有一块**大块晶盾板**，可独立破碎（做成 3 阶段裂纹） | 盾破后才暴露胸腔核心 |
| **爆裂型** | 全身布满**鼓胀的发光囊体**，体积最大，行动缓慢 | 囊体本身即弱点，命中任一囊体都算 |
| **牵引型** | 手臂延伸出**锚状晶钩**，肩部有绞盘结构 | 肩部绞盘是弱点 |
| **干扰型** | 头部是一个**多面棱镜结构**，身体较瘦，周身有小型悬浮碎片 | 头部棱镜 |

精英统一加一层"高价值目标"识别：**颈部/胸口一圈更亮的能量环**，四种精英共用同一个环网格，只换色。

### 2.5 僵尸玩家职业体（4 个，rev2 §4.3.2）

文档写明"职业与具体身体模板分离"，所以这 4 个不是新躯体，而是**职业标识挂件**，套在基础体/特殊体上。玩家死亡换体时挂件跟着走。

| 职业 | 挂件设计 | 说明 |
|---|---|---|
| **猎袭者** | 背部一对**折叠的晶体尖刺**（飞扑时展开），小腿加长 | 对应 6 米飞扑 |
| **巢群者** | 背部/腹部有**卵囊团**，会随召唤数量视觉增减（做 3 个 LOD 级别的囊团） | 对应召唤轮盘，最多 4 只 |
| **疫化者** | 双臂与胸口是**流动状半液体晶体**，脚下持续滴落 | 对应腐蚀投射物与污染区 |
| **铁壳者** | 正面躯干覆盖**厚重整块甲壳**，背面裸露 | 对应 120° 前方减伤 30%，**背面必须明显更脆弱** |

铁壳者的正背差异是玩法信息，必须做到位。

另外需要一个**玩家控制标识**：所有玩家操控的身体，头顶或胸口需要一个统一的发光标记（幸存者要能分辨"这是玩家不是 AI"）。

## 3. Boss（rev2.1：全局独立 Boss 池）

### 3.1 核心规则：只有 4 个 Boss，每个都是独立完整资产

V1 Boss 池固定为 4 个：

| Boss | 核心剪影 | V1 控制方式 | 地图限制 |
|---|---|---|---|
| **猎袭者 Boss** | 背部一对巨大镰刀状晶翼、前倾、爆发型四肢 | AI / Player 都支持 | **无**，四地图都可出现 |
| **巢群者 Boss** | 巨大开合式巢腔、囊体与召唤结构 | AI / Player 都支持 | **无**，四地图都可出现 |
| **疫化者 Boss** | 半液化下身、超长双臂、腐蚀腔体 | AI / Player 都支持 | **无**，四地图都可出现 |
| **铁壳者 Boss** | 正面塔盾级甲壳、背面明显薄弱 | AI / Player 都支持 | **无**，四地图都可出现 |

**禁止再建立以下资产：** `BossCanonical_v1_LOCKED`、`BOSS_Canonical`、Boss Base、Boss 母体、通用 AI Boss 躯体、单独的 Player Boss 躯体。

每个 Boss 必须自己拥有完整内容：

- 自己的完整 GLB
- 自己的 Skeleton / Bones / Rest Pose
- 自己的 Skinning 与动画 clips
- 自己的 Mesh 与 LOD（如使用 LOD）
- 自己的 PBR 材质与贴图，不使用其他 Boss 的贴图 atlas
- 自己的 Hitbox / Hurtbox / Collision
- 自己的胸腔弱点与弱点外壳
- 自己至少 3 个可拆卸/可破坏部件
- 自己的死亡裂解块（至少 8 块）
- 自己的 6 组 Boss 词缀可视附件
- 自己的 manifest / version

**可以共享的是游戏代码和接口规范，不是 Boss 内容资产。** 例如四个 Boss 都可以暴露 `idle / move / basic_attack / skill_a / skill_b / ultimate / hit / stagger / phase_break / death` 这些状态名，但每个 Boss 的动画文件必须属于自己。

### 3.2 Boss 与地图完全解耦

- 不存在“房屋 Boss”“草地 Boss”“沙漠 Boss”“地狱 Boss”。
- 地图生态只决定：场景模块、普通 Thrall/精英的生态挂件、普通敌人的材质/裂纹/音色。
- Boss 使用**自身固定视觉语言**，进入不同地图时不换皮、不换晶体形状、不换 Skeleton、不换材质套装。
- 4 个 Boss 都必须能在 4 个地图的 Boss 场中通过空间、碰撞、导航和相机测试，即 **4 Boss × 4 地图 = 16 组 smoke test**。
- Boss 体量仍建议高 4–5 米，正常水平占地不超过约 4 米直径，以满足多 Boss 12 米间距和 8 米安全复活点禁入区的空间规则。

### 3.3 同一个 Boss 同时用于 PvE 与玩家控制

**PvE：** 服务器从全局 Boss 池中选择一个 Boss，加载该 Boss 自己的资产并使用 `AIController`。

**非对称：** 玩家进入 Boss 阶段时仍加载**同一个 Boss 资产**，只把控制器改成 `PlayerController`。V1 沿用职业映射：

- 猎袭者 → 猎袭者 Boss
- 巢群者 → 巢群者 Boss
- 疫化者 → 疫化者 Boss
- 铁壳者 → 铁壳者 Boss

因此四个 Boss **全部既能 PvE，也能玩家操作**。玩家断线时 AI 接管也只是 `PlayerController → AIController`，重连后再切回；全过程 `boss_asset_id` 不变，不替换 GLB。

玩家控制标识建议使用运行时 HUD/VFX 标识，不为同一个 Boss 再制作一套“玩家版模型”。

### 3.4 四个 Boss 的独立造型要求

#### 猎袭者 Boss
- 背部镰刀状晶翼是主剪影，必须可参与技能展开/收拢。
- 身体前倾、腿部爆发感强，强调飞扑和追猎。
- 至少 3 个独立可破坏件：左右晶翼根部 + 胸腔核心罩。

#### 巢群者 Boss
- 腹部/胸腹形成巨大的开合式巢腔，召唤时机械/晶体式打开。
- 囊体、召唤口和背部孵化结构是主剪影。
- 至少 3 个独立可破坏件：左右巢囊 + 巢腔核心罩。

#### 疫化者 Boss
- 下半身呈稳定的半液化晶体结构，但仍要有明确碰撞边界，不能视觉体积和实际 Hitbox 差太大。
- 双臂极长，胸口/手臂有腐蚀发射腔。
- 至少 3 个独立可破坏件：左右臂外壳 + 胸腔核心罩。

#### 铁壳者 Boss
- 正面是塔盾级整块甲板，背面明显更薄、更暴露。
- 正背差异必须一眼可读，不能只靠贴图。
- 至少 3 个独立可破坏件：左右前甲板 + 中央胸甲/核心罩。

### 3.5 每个 Boss 自己的词缀附件（不是全 Boss 共用 6 个）

Day 20 起的 6 类 Boss 词缀逻辑保持，但**视觉资产按 Boss 分开制作**。也就是 4 个 Boss × 6 组 = **24 组 Boss 专属词缀视觉附件**。

| 词缀 | 每个 Boss 都必须有自己的版本 |
|---|---|
| 额外阶段 | 自己的副结构/副晶柱，不引用其他 Boss Mesh |
| 召唤节奏改变 | 自己的召唤节点/巢囊视觉 |
| 地形交互 | 自己的手臂/身体能量环结构 |
| 技能组合 | 自己的双节点/组合施法标识 |
| 针对救援 | 自己的扫描结构 |
| 护盾相位 | 自己的 3 片相位护盾/晶板 |

同一个 Boss 的 6 类附件必须能同时挂载而不互相穿插；不同 Boss 之间**不要求相同挂点位置、骨骼层级或网格形状**，只要求运行时能通过统一语义接口找到对应 socket。

## 4. 武器（rev2 §4.4、产品设计书 §8）

每把武器需要两个模型：**第一人称（FP，高精度）** + **第三人称/挂背（TP，低模）**。

### 4.1 初始武器（5 把，P7 阶段必须完成）

| 武器 | 造型要求 | 特殊建模需求 |
|---|---|---|
| **狙击枪** | 长枪管、大倍率镜、两脚架（可折叠）、枪托明显 | **镜片必须是独立网格 + 独立材质**（ADS 时要渲染镜内画面）；后坐恢复动画需要枪机可动 |
| **突击步枪** | 中等长度、中低倍瞄具、弹匣清晰 | 扩散状态机由服务器权威计算，客户端只做视觉——枪口需要**独立的枪口跳动骨骼** |
| **冲锋枪** | 短、紧凑、红点镜、高射速感 | 射速极高，**抛壳口要能挂粒子发射器**；每 tick 最多 2 发，抛壳要能合并播放 |
| **长矛** | 长杆 + 金属矛头 + 尾配重。全长 2–2.2 米 | 有格挡/蓄力姿态，需要**双手握持点**（前手可沿杆滑动）；胶囊扫掠命中，矛头要与碰撞胶囊对齐 |
| **剑** | 单手直刃剑 + 护手 + 圆头。刃长 90–100cm | 同上，格挡姿态需要剑身能立到身前；**刃口做单独材质**方便命中时发光 |

近战不做 rewind（服务器权威），意味着 150ms 延迟下会有可感的命中延迟——**建模时把挥砍轨迹做长一点、拖影范围留大一点**，这是文档 P7 要求人工评审手感的部分。

### 4.2 进阶武器（金卡及以上，P13 完成）

进阶武器是**三阶段升级链**，同链升级原位替换，所以每条链需要 3 个可辨识的阶段模型（可以共用基础网格，逐级加部件）。

| 链 | 阶段 1（原型） | 阶段 2 | 阶段 3 |
|---|---|---|---|
| **光剑链** | 原型光剑：粗糙握柄 + 不稳定刃（刃缘抖动） | 光剑：稳定刃 + 完整握柄 | 完全体：双刃或加长刃 + 握柄能量环 |
| **激光枪链** | 激光枪：管状发射器 + 散热片 | `S161 聚变激光`（钻石）：散热片加大、可见热量条 | — |
| **等离子链** | 等离子炮：粗管 + 前端环形加速器 | `S162 奇点等离子炮`（黑金）：前端加装**双环反向加速结构** | — |
| **法杖链** | 元素法杖：木/金属杖身 + 顶端晶石 | 奇点法杖：顶端晶石变为悬浮的黑色球体 + 环绕碎片 | — |

**热量可视化**是硬需求：`S161 聚变激光` 有"热量增长 −20%、弱点命中散热"机制，所以激光枪链必须有**可随热量变色的散热部件**（材质参数驱动，不要新几何）。

`S162` 命中产生 4 米吸引 2 秒后爆发，武器本体不需要额外几何，但需要一个**吸引场的球形网格**（见 §7）。

## 5. 消耗品与部署物（rev2 §4.4.2：3 个消耗品槽 + 1 个部署物槽）

### 5.1 消耗品（4 个，每个要 3 个状态）

每个消耗品需要：**世界掉落模型**（会旋转发光）+ **第一人称手持模型** + **HUD 图标源**。

| 道具 | 造型 |
|---|---|

### 5.2 部署物（4 个 + 守卫晶盾）

部署物有**位置合法性与总数量限制**，玩家需要放置预览，所以每个都要一个**半透明预览版材质态**。

| 部署物 | 造型 | 特殊需求 |
|---|---|---|
| **自动炮塔** | 三脚架 + 可旋转炮塔头 + 弹链 | 炮塔头需要独立骨骼（会转向追踪目标）；被摧毁要有 2 阶段损坏态 |

| **无人机** | 小型悬浮体，4 个推进环 + 中央传感器 | 全程悬浮，需要待机/移动/攻击三种姿态骨骼 |
| **守卫晶盾** | 180 HP、每秒衰减 12、最长 8 秒 | 一片**弧形晶体板**，必须做 **4 个损坏阶段**（100/75/50/25%）；被击破时有 2 秒补偿效果，需要碎裂动画。注意：**只挡投射物与近战，不挡 Boss 大招与地面范围**——所以晶盾要做成**不封顶、不落地的悬浮弧板**，视觉上就要看出来它挡不住地面效果 |

## 6. 地图模块（rev2 §4.2、P6 阶段 —— 工作量最大的一块）

### 6.1 关键约束

- V1 **不做完整程序化生成**，改用"人工制作的预制模块 + 整数网格摆放 + 4 种旋转"
- **碰撞体与 navmesh 必须随资产预烘焙**，不在运行时生成——这是建模交付物的一部分，不是程序的事
- 每个模块必须有**标准化连接口**（同一尺寸、同一高度、同一朝向规范），否则拼不上
- 模块定版后改几何会导致 `layout_hash` 不匹配、客户端直接拒绝进入。**先定尺寸规范，再开始做**

**建议网格规范**：单格 8m × 8m，墙高 4m，门洞宽 2.4m × 高 2.8m，连接口居中。

### 6.2 每个生态需要的模块类型

每生态至少需要这 4 类（rev2 §4.2 明确列出）：房间 / 走廊 / 开阔地 / Boss 场。实际做起来每生态约 12–16 个模块。

#### 房屋（简单，同屏 20 敌，近距离瓶颈伏击）
- 走廊（直、L 形、T 形、十字）
- 房间（小卧室、大客厅、厨房、储藏间）
- 楼梯间（连接楼层）
- 门窗（**门必须是可动的独立网格**——环境事件有"封门"）
- Boss 场：大厅或中庭，挑高
- 环境事件相关：**可熄灭的灯具**（停电）、警报器、可封锁的门
- 配色：暖木色 + 米黄墙 + 紫色晶体侵蚀区

#### 草地（普通，同屏 30 敌，长距离射击与包围）
- 开放地形块（缓坡、平地）
- 树林块（树是独立资产，5–6 种，用于遮挡）
- 围栏段（可破坏）
- 小型建筑（谷仓、棚屋、水塔）
- Boss 场：开阔平地 + 环形低矮遮挡
- 环境事件：雾（体积雾，无需建模）、暴雨、**草地火线**（需要可燃草地贴片）
- 配色：黄绿 + 土棕 + 绿色孢子晶体

#### 沙漠（困难，同屏 40 敌，能见度与移动管理）
- 沙丘块（高低起伏，注意可攀爬性）
- 遗迹块（断柱、残墙、拱门）
- 峡谷段（两侧高墙，形成通道）
- 低掩体（碎石、残墙、翻倒的车）
- Boss 场：遗迹广场
- 环境事件：沙尘暴（粒子）、热浪、**流沙区**（需要地面下陷网格）
- 配色：沙黄 + 赭石 + 风化米白 + 琥珀色晶体

#### 地狱（地狱难度，同屏 50 敌，持续区域危险）
- 熔岩裂隙（**发光地面网格**，是危险区）
- 祭坛（Boss 场核心）
- 桥梁（窄，两侧无护栏，制造压迫）
- 洞穴段（封闭，顶部有钟乳石状晶体）
- Boss 场：祭坛平台 + 环形熔岩
- 环境事件：熔岩喷发（需要喷发口网格）、火雨、诅咒区
- 配色：黑曜黑 + 橙红熔岩发光 + 暗红岩

**注意**：地狱同屏 50 个敌人，是最吃性能的生态。地狱模块的面数要压到其他生态的 70%，多用贴图和法线，少用几何细节。

### 6.3 四生态通用的功能物件（每个都要做，且四生态各一套外观）

这些是玩法必需的，很容易漏：

| 物件 | 用途 | 建模要求 |
|---|---|---|
| **玩家出生区标识** | manifest 里的 `出生区` | 地面标记 + 可发光边界，必须在远处可见 |
| **僵尸 spawn zone 标识** | 召唤合法区（僵尸玩家能看到） | 只对僵尸阵营可见的地面网格 |
| **安全复活点** | 救援成功后在此复活；Boss 8 米禁入区 | 一个明显的**柱状/环状结构**，要能显示 8 米禁入范围 |
| **补给点** | Day 过渡的补给阶段 | 可开启的箱体，带 3 种状态（未开/开启中/已空） |
| **目标点** | 推进 Boss 进度的地图目标 | 可交互的装置，带进度环挂点 |
| **危险区边界** | 熔岩/流沙/诅咒区 | 统一的边界指示网格，四生态换材质 |

## 7. VFX 用网格（rev2 §4.9.1，有独立 8MB 预算）

这些不是"角色"，但确实要建模：

| 资产 | 规格 |
|---|---|
| **晶体碎片** | 每次击杀生成 10–20 片。做 **6–8 种碎片形状**，四生态各一套（形状必须不同：房屋短粗六棱、草地圆润带丝、沙漠扁平、地狱长尖刺）。**必须用 GPU instancing**，禁止每次命中创建新 Mesh |
| **弱点核心** | 一个发光球体 + 一层可碎外壳（分 3 片） |
| **护盾半球** | 护盾发生器与部分技能共用 |
| **奇点吸引场** | `S162` 用的 4 米球体，带内向流动的 UV |
| **地面法阵/领域环** | 法师冰霜领域、战吼范围、治疗脉冲共用一个环形平面网格，换材质 |
| **命中裂纹** | 不是几何，是共享 shader 的遮罩——但要求所有敌人 UV 预留裂纹通道 |

晶片池上限：Low/Medium/High 为每次 10/14/20，全局 80/168/320。池满时整次退化为 GPU 粒子——**所以碎片模型必须极简，每片 ≤50 面**。

## 9. 总量与优先级（对应 rev2 的 P 阶段）

| 阶段 | 需要交付的模型 | 大致数量 |
|---|---|---:|

**合计约 155–180 个独立网格/附件组**（不含 LOD 与碎片变体）。增加量主要来自 4 个 Boss 各自拥有完整资产与 24 组专属词缀附件。

### 建议的实际开工顺序

1. **先定规范**：网格尺寸、连接口标准、骨骼、挂点命名、材质四分层、UV 裂纹通道。规范没定就开工，P6 会全部返工。
2. **先做一个完整垂直切片**：基础结晶体（草地）+ 突击步枪 + 战士 + 3 个草地模块。用它验证面数预算和手机 30fps 是否成立。
3. **再铺量**：地图模块是最大工作量（约占一半），但也是最能外包/复用 trim sheet 的部分。
4. **角色放到 P8**：rev2 特意把职业从 P3 后移到 P8，理由是"核心 Day、Boss、卡牌、地图都还没做"。建模也应该跟着这个顺序——**不要一开始就把 5 个角色都做完**，因为技能的视觉需求会随着 P4/P5 的实现而变。

## 10. 容易被漏掉的几项（点名提醒）

1. **每个模块的碰撞体与 navmesh 是建模交付物**，不是程序生成的（rev2 §4.2 写死了"随资产预烘焙"）。
2. **可动的门**——房屋生态有"封门"环境事件，门必须是独立可动网格且带碰撞开关。
3. **可熄灭的灯具**——"停电"事件需要灯具能切换发光态。
4. **铁壳者的背面必须明显更脆弱**，这是玩法信息不是装饰。
5. **玩家操控体的统一标识**——幸存者必须能分辨"这个僵尸是玩家还是 AI"。
6. **倒地待救援的姿势不能是尸体**，无血约束在这里最容易破功。
7. **急救包不要用红十字**——红十字标志受《日内瓦公约》保护，且违反"无饱和红闪"的可访问性要求。用青绿。
8. **狙击镜片要独立网格独立材质**，ADS 需要渲染镜内。
9. **晶盾要做成悬浮弧板**，因为它挡不住 Boss 大招和地面效果，外形必须诚实地传达这一点。
10. **地狱生态面数要额外压缩**，因为同屏 50 个敌人。
11. **Boss 不得带 biome/生态命名或依赖**：不要出现 `BOSS_grass` / `BOSS_hell` 之类资产。
12. **同一 Boss 的 AI/PvE 与玩家控制必须是同一 GLB**；禁止复制一份做 `_AI`、一份做 `_Player`。
13. **Boss 之间不得共享母体、Skeleton、动画文件或材质贴图资产**；只允许统一接口规范。
